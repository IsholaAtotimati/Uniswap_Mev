**Location**: [src/ExecutionCoordinator.sol](src/ExecutionCoordinator.sol) → `coordinateSubmission()` 
**Function Metrics**: Min **88,709** | Avg **200,569** | Max **312,430** gas

**Breakdown**:
- Payload verification: ~37,000 gas
- Risk assessment: ~9,300 gas
- Decision aggregation: ~1,200 gas
- Risk snapshot storage: ~114,500 gas
- Settlement authorization: ~75,000 gas
- Fee application: ~26,700 gas
- Event emissions (2 events): ~1,000 gas
- **Total: ~265,000 gas (avg execution)**

**Current Implementation**:
```solidity
// In ExecutionCoordinator.coordinateSubmission():
mevHook.verifyPayload(key, payload, attestations);           // ~37k
(bool riskOk, uint24 fee) = mevHook.assessRiskPolicy(payload); // ~10k
DecisionAggregator.aggregateDecision(...);                     // ~1.2k
mevHook.storeRiskSnapshot(...);                                // ~114k
settlementId = mevHook.authorizeSettlement(...);               // ~75k
mevHook.applyFee(key, fee);                                    // ~26k
```

**Optimization Opportunities**:
- Batch storage operations (risk + settlement in one tx)
- Cache pool lookups where possible
- Minimize state reads in risk assessment

### Signature Verification

**Location**: [src/SignatureEngine.sol](src/SignatureEngine.sol) → `_verifyPayload()`

**Breakdown**:
- Nonce/expiry validation: **< 1,000** gas
- Payload hashing: **~2,235** gas
- Ecrecover (precompile): **~3,000** gas per signature
- Quorum threshold check: **< 1,000** gas
- Total per signature: **~6,235** gas
- Total for single attestation: **37,276** gas (includes framing + storage)

**Performance Notes**:
- Ecrecover is the dominant cost (precompile at 3000 gas)
- Quorum validation loops are O(n) but typically n ≤ 3
- Cannot optimize precompile; batch verification recommended for high volume

## Regression Tracking

### How to Monitor

Run before each commit:
```bash
cd /home/lukman12/MEV-SHIELD
forge test --gas-report > gas-report-$(date +%Y%m%d-%H%M%S).txt
```

### Acceptable Variance

- **Green** (< 5% increase): No action required
- **Yellow** (5–10% increase): Review optimization opportunities
- **Red** (> 10% increase): Investigate regression; may require refactoring
